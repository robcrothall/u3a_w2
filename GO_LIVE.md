# Going live: publishing the member site on u3aportalfred.org.za

The public home page is already live. Going live adds the members' area (login, events,
recordings, payments, admin) to the same domain. It needs a **production database** and
**.env**, so the test site's data and settings are never shared with the live site.

A push to `main` deploys to `public_html/`. Nothing below touches the live site until step 7.

## A. Prepare production (no visible change to the public)

1. **cPanel > MySQL Databases:** create a new database (for example `<account>_u3a`) and a new
   user with a strong password; add the user to the database with ALL PRIVILEGES.
   Use a different database and user from the test site.
2. **Create `.env` in your home directory** (next to `public_html`, NOT inside it).
   Copy `.env.example`, set `APP_ENV=production`, the new `DB_*` values, new random
   16-character `ENCRYPTION_KEY` / `ENCRYPTION_IV`, `SITE_URL=https://u3aportalfred.org.za`
   and `MAIL_FROM=info@u3aportalfred.org.za`. Set file permissions to 600.
3. **phpMyAdmin > the production database > Import**, in this order:
   `sql/migrations/001` ... `005`, then `import_members.sql` (generated by
   `tools/import_members.php`; it contains personal data and is never in git).
4. **Check email works from the host.** On the test site use "Forgotten your password?" with
   your own address and confirm the message arrives (check spam).

## B. Go live

5. Confirm the test site (https://w2.u3aportalfred.org.za) behaves as expected.
6. Take a backup of `public_html` (cPanel > Backup, or download with FileZilla).
7. Merge `staging` into `main` and push (ask Claude, or `git checkout main`,
   `git merge staging`, `git push`). The GitHub Action uploads the site.
8. Open https://u3aportalfred.org.za: the home page looks the same, with the member menu.
9. Use "Forgotten your password?" with the admin email to set your password, then log in.
   The import already gave that account the admin role.
10. Admin > Password invitations: send invitations in batches of 40.

## If something goes wrong

* The home page falls back to the plain static page by itself when `.env` or the database
  is unavailable, so visitors never see an error.
* To take the member pages off again, revert the merge on `main` and push; the Action
  removes the files it deployed.
* Production data is never touched by deployments: `.env` lives outside `public_html`, and
  uploads are excluded from the sync.
